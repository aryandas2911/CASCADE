== 2. DATABASE DESIGN PRINCIPLES ==

The database architecture follows these core principles:

PostgreSQL as the Source of Truth

All persistent workflow metadata, execution history, checkpoints, and
configuration are stored in PostgreSQL.

Stateless Workers

Workers never own persistent state. They retrieve state from the database
when required.

Immutable Execution History

Execution records are append-only wherever possible to preserve replayability
and auditing.

Normalized Metadata

Workflow metadata remains normalized to reduce duplication while execution
logs may be partially denormalized for analytical queries.

Idempotent Writes

All database operations must safely tolerate retries.

== 3. STORAGE ARCHITECTURE ==

PostgreSQL

Source of truth. Stores metadata, workflow state, checkpoints, scheduler
state, routing policies, users, organizations, API keys, metrics summaries.

Redis

Ephemeral queues, locks, distributed coordination, rate limits, worker
heartbeats, temporary caches.

Object Storage (S3/MinIO)

Large artifacts:
- prompts
- outputs
- checkpoints
- execution snapshots
- traces
- logs

ClickHouse (optional but recommended)

Time-series analytics.

Vector Database (Qdrant)

Semantic cache.

PART 4: SECURITY ARCHITECTURE
================================================================================

== 1. SECURITY GOALS & PRINCIPLES ==

Goals:
- Protect workflow definitions, execution metadata, checkpoints, cached
  outputs, secrets, and APIs.
- Assume zero-trust between clients and services.
- Security-by-default with least privilege.

Security Principles:
- Least privilege
- Defense in depth
- Zero trust
- Fail securely
- Secure defaults
- Explicit authorization
- Observability
- Immutable audit trail
- Privacy by design

== 2. IDENTITY & AUTHENTICATION ==

Human Users:
- OAuth 2.0 / OpenID Connect (GitHub, Google, Microsoft) for web login.
- JWT access tokens (short-lived) and refresh tokens.
- Optional MFA support.
- Session revocation.

Service-to-Service:
- Mutual TLS (mTLS).
- Service identities.
- Short-lived signed service tokens.

API Authentication:
- API keys for programmatic access.
- Scoped keys.
- Rotation and expiration.
- Per-key quotas.
